## 1. 受控工程原则

### 1.1 六大核心原则

| 原则 | 定义 | 系统实践 | 验证方式 |
|------|------|----------|----------|
| **可观察性（Observability）** | 任何内部状态可通过外部输出推断 | 全链路 Trace + Metrics + 结构化日志 | 故障场景下5分钟内定位问题根因 |
| **可控制（Controllability）** | 任何操作可暂停、回滚、审批 | 工作流状态机 + 人工确认点 + 熔断开关 | 紧急情况下30秒内停止任何流程 |
| **可验证（Verifiability）** | 任何输出可审计、可对比、可复现 | 不可变快照 + 版本对比 + 沙箱验证 | 任意时刻可重建过去任意版本索引 |
| **可恢复（Recoverability）** | 故障后快速恢复到已知良好状态 | 自动快照 + 一键回滚 + 多副本冗余 | RTO < 5分钟，RPO < 1分钟 |
| **安全默认（Secure by Default）** | 默认拒绝、最小权限、零信任 | RBAC + 数据隔离 + 加密传输存储 | 安全审计通过率100% |
| **渐进发布（Progressive Delivery）** | 变更逐步暴露，风险逐步释放 | 金丝雀 + 蓝绿 + A/B + Feature Flag | 生产故障率 < 0.1% |

### 1.2 控制点矩阵

```
                    可观察   可控制   可验证   可恢复   安全默认  渐进发布
代码解析              ●       ●       ●       ●       ●       ●
向量索引              ●       ●       ●       ●       ●       ●
图索引                ●       ●       ●       ●       ●       ●
日志检索              ●       ●       ○       ○       ●       ○
LLM调用              ●       ●       ●       ○       ●       ○
诊断报告              ●       ●       ●       ○       ●       ○
增量更新              ●       ●       ●       ●       ●       ●
培训问答              ●       ○       ○       ○       ●       ○

● = 强控制  ○ = 弱控制
```

### 2.2 控制流与数据流分离

```
控制流（Control Plane）：策略 → 审批 → 编排 → 监控
    │
    │ 指挥/约束
    ▼
数据流（Data Plane）：代码 → 解析 → 索引 → 检索 → 诊断
    │
    │ 反馈/状态
    ▼
控制流（状态上报、异常告警）
```

**关键设计**：控制平面可独立升级/回滚，不影响数据平面运行。

### 2.3 现代运行基线：Java 21 LTS + Maven 4

为充分发挥 IO 密集型场景的性能优势并简化构建，系统统一采用以下运行与构建基线：

| 组件 | 选型 | 关键特性 |
|------|------|----------|
| **JDK** | Java 21 LTS | 虚拟线程（Virtual Threads）、Structured Concurrency、Records、Sealed Classes、Pattern Matching for switch |
| **构建工具** | Maven 4 | 构建缓存（Build Cache）、Consumer/Build POM 分离、更简洁的 POM 模型 |
| **框架** | Spring Boot 3.4+ | 原生支持虚拟线程、`spring.threads.virtual.enabled=true` |
| **工作流** | Temporal Java SDK 1.26+ | 需验证与虚拟线程的兼容性 |

**虚拟线程适用场景**：
- LLM 调用、外部 API 调用
- 多仓库并行代码解析的编排
- RAG 检索中 Qdrant / Neo4j / 日志索引的并发查询
- 审计异步写入

**虚拟线程注意事项**：
- 仅用于 IO 密集型任务；CPU 密集型 AST 解析仍使用平台线程或独立 Worker。
- 避免线程钉住（thread pinning）：将 `synchronized` 替换为 `ReentrantLock`，并通过 `-Djdk.tracePinnedThreads=full` 在测试环境检测。
- 第三方驱动（Qdrant、Neo4j、Temporal SDK）需确认虚拟线程兼容性。

```
com.company.intelligent-diagnosis.data
├── agent-api                 # API 层（REST Controller）
├── agent-application         # 应用服务层
├── agent-domain              # 领域层

```

**模块说明**：
- `shared-contracts` 集中生成 Java gRPC stub，供 `data-plane` 与 `java-parser` 共用，避免重复生成与版本不一致。
- 每个 Parse Worker 为独立可执行模块，可独立扩缩容；目前优先支持 Java 与 C#。

### 4.3 模块交互原则

```
控制平面 ──策略约束──→ 数据平面
    ↑                    │
    └────状态上报────────┘

规则：
1. 控制平面可独立升级，不影响数据平面
2. 控制平面故障时，数据平面按最后已知策略继续运行
3. 数据平面所有操作必须上报控制平面审计
4. 控制平面策略变更需版本化，可回滚
```

## 5. 数据模型设计

#### Policy（策略定义）

采用 Java `record` 保证不可变性，符合受控工程的可验证与审计要求。

```java
public record Policy(
    String id,                    // 策略ID
    String name,                  // 策略名称
    PolicyType type,              // 策略类型
    String regoCode,              // OPA/Rego 策略代码
    int version,                  // 版本号
    PolicyStatus status,          // 状态（草稿/生效/废弃）
    String createdBy,             // 创建人
    Instant createdAt,            // 创建时间（UTC）
    Instant effectiveAt,          // 生效时间
    List<String> appliesTo        // 适用范围（服务/角色/操作）
) {}

public enum PolicyType {
    SECURITY,        // 安全策略（代码扫描、权限控制）
    COMPLIANCE,      // 合规策略（数据保留、访问审计）
    OPERATIONAL,     // 运维策略（发布窗口、资源限制）
    QUALITY          // 质量策略（准确率阈值、覆盖率）
}
```

### 5.2 不可变快照实体

```java
public class IndexSnapshot {
    private String snapshotId;              // 快照ID（仓库+commit+时间戳）

    private String branch;                  // 分支
    private String commitHash;              // Commit Hash
    private String commitMessage;           // Commit Message
    private String author;                  // 提交者
    private SnapshotType type;              // 快照类型
    private SnapshotStatus status;          // 状态
    private String qdrantSnapshot;          // Qdrant 快照名
    private String neo4jBackup;             // Neo4j 备份名
    private String metadataPath;            // 元数据存储路径
```

## 6. 多语言代码解析层

### 6.1 设计原则：语言原生解析 + 统一契约

为避免 Java 进程直接调用各语言 AST 工具带来的生态割裂和沙箱复杂度，解析层采用 **Parse Worker 架构**：

- 每个 Worker 使用对应语言的原生解析生态（Roslyn、JavaParser、TypeScript Compiler API、go/ast、tree-sitter）。
- Worker 作为独立容器部署，通过 gRPC + Protobuf 与 Java 编排服务通信。
- 编排服务负责：变更检测、安全扫描、风险分类、审批流程、结果聚合。
- 沙箱隔离直接作用于 Worker 容器（资源限制、只读文件系统、无网络）。

### 6.2.1 契约模块：shared-contracts

为避免 `data-plane` 与 `java-parser` 分别生成 Protobuf 代码导致版本不一致，`parse.proto` 统一由根模块 `shared-contracts` 生成 Java gRPC stub：

- C# Parse Worker 使用同一 `.proto` 文件生成 C# 契约，实现跨语言共享。

### 6.4 Parse Worker 客户端：ParseWorkerClient

```java
public class ParseWorkerClient {

    private final ParseWorkerProperties properties;
    private final Map<String, ManagedChannel> channels = new ConcurrentHashMap<>();

    public List<CodeElement> parse(String language, ParseRequest request) {
        Endpoint endpoint = properties.endpointFor(language);
        ManagedChannel channel = channels.computeIfAbsent(language, k -> createChannel(endpoint));
        ParseWorkerGrpc.ParseWorkerBlockingStub stub = ParseWorkerGrpc
            .newBlockingStub(channel)
            .withDeadlineAfter(30, TimeUnit.SECONDS);
        ParseResponse response = stub.parse(request);
        return response.getElementsList().stream()
            .map(CodeElementMapper::toDomain)
            .toList();
    }
}
```

```java
        String auditId = auditService.startAudit("GRAPH_BUILD", Map.of("repo", repository, "count", elements.size()));

        try {
            // 1. 策略检查
            PolicyResult policy = policyEngine.evaluate("GRAPH_BUILD", 
                Map.of("repository", repository, "elementCount", elements.size()));
            if (!policy.isAllowed()) {
                return GraphBuildResult.rejected(policy.getReason());
            }

            // 2. 创建前置快照（回滚点）
            IndexSnapshot beforeSnapshot = versionControl.createSnapshot(repository, "pre-build-" + System.currentTimeMillis());

            // 3. 执行构建
            graphBuilder.buildGraph(repository, elements);

            // 4. 验证一致性
            ConsistencyCheck consistency = verifyConsistency(repository);
            if (!consistency.isValid()) {
                // 自动回滚
                versionControl.rollbackTo(beforeSnapshot.getSnapshotId());
                auditService.failAudit(auditId, "CONSISTENCY_FAILED", consistency.getErrors());
                return GraphBuildResult.failed("Consistency check failed, auto-rolled back");
            }

            // 5. 创建后置快照
            IndexSnapshot afterSnapshot = versionControl.createSnapshot(repository, "post-build-" + System.currentTimeMillis());

            auditService.completeAudit(auditId, "SUCCESS", afterSnapshot.getSnapshotId());

            return GraphBuildResult.success(beforeSnapshot, afterSnapshot);

        } catch (Exception e) {
            auditService.failAudit(auditId, "EXCEPTION", e.getMessage());
            throw e;
        }
    }

        // 向量中的调用关系 == 图中的 CALLS 边数
```

```java
@Service

    private final AuditService auditService;

            PolicyResult policy = policyEngine.evaluate("RETRIEVE",
                Map.of("userId", userId, "service", service));
            if (!policy.isAllowed()) {
                auditService.failAudit(auditId, "ACCESS_DENIED", policy.getReason());
                throw new AccessDeniedException(policy.getReason());

            auditService.completeAudit(auditId, "SUCCESS",
                Map.of("codeCount", context.getRelatedCode().size(),
                       "logCount", context.getRelatedLogs().size()));

            return context;

        } catch (Exception e) {
            auditService.failAudit(auditId, "ERROR", e.getMessage());
            throw e;
        }
    }

    private RetrievalContext retrieveConcurrently(String query, String errorInfo, String service) {
        try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
            Future<List<CodeSnippet>> vectorFuture = scope.fork(() -> vectorRetriever.search(query, errorInfo, service));
            Future<List<GraphNode>> graphFuture = scope.fork(() -> graphRetriever.search(query, errorInfo, service));
            Future<List<LogEntry>> logFuture = scope.fork(() -> logRetriever.search(query, errorInfo, service));

            scope.join();
            scope.throwIfFailed();

            return RetrievalContext.builder()
                .relatedCode(vectorFuture.resultNow())
                .relatedGraphNodes(graphFuture.resultNow())
                .relatedLogs(logFuture.resultNow())
                .build();
        }
    }
}
```

### 9.1 受控 LLM 调用

```java
@Service
@Slf4j
public class ControlledLLMService implements LLMService {

    private final PromptSanitizer sanitizer;
    private final OutputValidator validator;
    private final CostTracker costTracker;
    private final CircuitBreaker circuitBreaker;
    private final AuditService auditService;
    private final LLMProvider primaryProvider;
    private final LLMProvider fallbackProvider;

    // 虚拟线程执行器：专用于 IO 密集型 LLM 调用
    private final ExecutorService virtualExecutor = Executors.newVirtualThreadPerTaskExecutor();

    public ControlledLLMService(/* dependencies */) {
        // constructor injection
    }

    @Override
    public String complete(String prompt) {
        if (!circuitBreaker.allowRequest()) {
            throw new ServiceUnavailableException("LLM circuit breaker open");
        }

        String auditId = auditService.startAudit("LLM_CALL", Map.of("promptHash", HashUtils.sha256(prompt)));

        try {
            String safePrompt = sanitizer.sanitize(prompt);

            if (!costTracker.checkBudget(safePrompt)) {
                auditService.failAudit(auditId, "BUDGET_EXCEEDED", "LLM cost budget exceeded");
                throw new BudgetExceededException("LLM cost budget exceeded");
            }

            // 主模型调用，超时后降级
            String response = callWithFallback(safePrompt, Duration.ofSeconds(30));

            ValidationResult validation = validator.validate(response);
            if (!validation.isValid()) {
                circuitBreaker.recordFailure();
                auditService.failAudit(auditId, "OUTPUT_REJECTED", validation.getReason());
                throw new InvalidOutputException(validation.getReason());
            }

            circuitBreaker.recordSuccess();
            costTracker.recordCost(auditId, safePrompt, response);
            auditService.completeAudit(auditId, "SUCCESS", Map.of("outputHash", HashUtils.sha256(response)));

            return response;

        } catch (Exception e) {
            circuitBreaker.recordFailure();
            auditService.failAudit(auditId, "ERROR", e.getMessage());
            throw e;
        }
    }

    private String callWithFallback(String prompt, Duration timeout) {
        try {
            return callWithTimeout(primaryProvider, prompt, timeout);
        } catch (TimeoutException | LLMInvocationException e) {
            log.warn("Primary LLM provider failed, falling back: {}", e.getMessage());
            return callWithTimeout(fallbackProvider, prompt, timeout);
        }
    }

    private String callWithTimeout(LLMProvider provider, String prompt, Duration timeout) {
        try {
            return CompletableFuture
                .supplyAsync(() -> provider.complete(prompt), virtualExecutor)
                .orTimeout(timeout.toMillis(), TimeUnit.MILLISECONDS)
                .join();
        } catch (CompletionException e) {
            Throwable cause = e.getCause();
            if (cause instanceof TimeoutException) {
                throw new LLMInvocationException("LLM call timeout", cause);
            }
            throw new LLMInvocationException("LLM call failed", cause);
        }
    }
}

public interface LLMProvider {
    String complete(String prompt);
}
```

**关键改进**：
- 使用虚拟线程执行器替代默认 `ForkJoinPool`，避免阻塞计算线程。
- 主模型超时或失败后自动降级到备用模型。
- 正确处理 `CompletionException` 包装，区分超时与调用失败。
- `LLMProvider` 接口解耦具体供应商，避免 Kimi / OpenAI 锁定。

### 10.1 Temporal 工作流实现

```java
@WorkflowInterface
public interface IndexUpdateWorkflow {

    @WorkflowMethod
    UpdateResult update(GitPushEvent event);

    @SignalMethod
    void approve(String approver, String comment);

    @SignalMethod
    void reject(String reason);

    @SignalMethod
    void pause(String reason);

    @SignalMethod
    void resume();

    @SignalMethod
    void rollback();

    @QueryMethod
    UpdateStatus getStatus();

    @QueryMethod
    List<WorkflowStep> getStepHistory();
}

public class IndexUpdateWorkflowImpl implements IndexUpdateWorkflow {

    private UpdateStatus status = UpdateStatus.PENDING;
    private List<WorkflowStep> steps = new ArrayList<>();
    private boolean approved = false;
    private String rejectionReason;
    private boolean paused = false;
    private String pauseReason;
    private boolean rollbackRequested = false;

    @Autowired private IndexUpdateActivities activities;

    @Override
    public UpdateResult update(GitPushEvent event) {
        // 1. 变更检测
        step("DETECT_CHANGES", () -> activities.detectChanges(event));

        // 2. 安全扫描
        step("SECURITY_SCAN", () -> activities.scanSecurity(event));

        // 3. 风险分类
        RiskLevel risk = step("CLASSIFY_RISK", () -> activities.classifyRisk(event));

        // 4. 高风险审批
        if (risk == RiskLevel.HIGH) {
            status = UpdateStatus.AWAITING_APPROVAL;
            Workflow.await(() -> approved || rejectionReason != null);

            if (rejectionReason != null) {
                status = UpdateStatus.REJECTED;
                return UpdateResult.rejected(rejectionReason);
            }
        }

        // 5. 创建前置快照
        Snapshot beforeSnapshot = step("CREATE_SNAPSHOT", () -> activities.createSnapshot(event));

        // 6. 沙箱解析
        List<CodeElement> elements = step("PARSE", () -> activities.parseInSandbox(event));

        // 7. 验证输出
        step("VALIDATE_OUTPUT", () -> activities.validateOutput(elements));

        // 8. 写入临时索引
        step("WRITE_TEMP_INDEX", () -> activities.writeTempIndex(event, elements));

        // 9. 金丝雀验证
        step("CANARY_VERIFY", () -> activities.canaryVerify(event));

        // 检查暂停信号
        if (paused) {
            status = UpdateStatus.PAUSED;
            Workflow.await(() -> !paused);
        }

        // 检查回滚信号
        if (rollbackRequested) {
            step("ROLLBACK", () -> activities.rollbackTo(beforeSnapshot));
            status = UpdateStatus.ROLLED_BACK;
            return UpdateResult.rolledBack("Manual rollback requested");
        }

        // 10. 全量发布
        step("PROMOTE", () -> activities.promoteToProduction(event, elements));

        // 11. 创建后置快照
        Snapshot afterSnapshot = step("CREATE_POST_SNAPSHOT", () -> activities.createSnapshot(event));

        status = UpdateStatus.COMPLETED;
        return UpdateResult.success(elements.size(), beforeSnapshot, afterSnapshot);
    }

    @Override
    public void approve(String approver, String comment) {
        approved = true;
        activities.recordApproval(approver, comment);
    }

    @Override
    public void reject(String reason) {
        rejectionReason = reason;
    }

    @Override
    public void pause(String reason) {
        paused = true;
        pauseReason = reason;
    }

    @Override
    public void resume() {
        paused = false;
    }

    @Override
    public void rollback() {
        rollbackRequested = true;
    }

    @Override
    public UpdateStatus getStatus() {
        return status;
    }

    @Override
    public List<WorkflowStep> getStepHistory() {
        return steps;
    }

    private <T> T step(String name, Supplier<T> action) {
        WorkflowStep step = new WorkflowStep(name, WorkflowStepStatus.RUNNING, Instant.now());
        steps.add(step);

        try {
            T result = action.get();
            step.setStatus(WorkflowStepStatus.COMPLETED);
            step.setCompletedAt(Instant.now());
            return result;
        } catch (Exception e) {
            step.setStatus(WorkflowStepStatus.FAILED);
            step.setError(e.getMessage());
            step.setCompletedAt(Instant.now());
            throw e;
        }
    }
}
```

### 11.2 审计中心实现

```java
@Service
@Slf4j
public class ImmutableAuditService {

    private final PostgreSQLAuditRepository primaryRepository;
    private final AzureBlobStorage coldStorage;
    private final CryptographicSigner signer;

    // 虚拟线程执行器：IO 密集型审计写入
    private final ExecutorService virtualExecutor = Executors.newVirtualThreadPerTaskExecutor();
    private final BlockingQueue<AuditEntry> auditQueue = new LinkedBlockingQueue<>(10000);

    @PostConstruct
    public void init() {
        virtualExecutor.submit(this::asyncWrite);
    }

    @PreDestroy
    public void shutdown() {
        virtualExecutor.shutdown();
        try {
            if (!virtualExecutor.awaitTermination(30, TimeUnit.SECONDS)) {
                virtualExecutor.shutdownNow();
            }
        } catch (InterruptedException e) {
            virtualExecutor.shutdownNow();
            Thread.currentThread().interrupt();
        }
    }

    /**
     * 启动审计记录
     */
    public String startAudit(String action, Map<String, Object> context) {
        AuditEntry entry = new AuditEntry(
            UUID.randomUUID().toString(),
            MDC.get("traceId"),
            SecurityContext.getCurrentUser().getId(),
            SecurityContext.getCurrentUser().getTenantId(),
            AuditAction.valueOf(action),
            null,
            null,
            null,
            null,
            maskSensitiveData(context),
            RequestContext.getClientIp(),
            RequestContext.getUserAgent(),
            Instant.now(),
            null,
            null
        );

        entry = entry.withSignature(signer.sign(entry.toSignableString()));
        auditQueue.offer(entry);

        return entry.id();
    }

    /**
     * 完成审计记录
     */
    public void completeAudit(String auditId, String result, Map<String, Object> details) {
        AuditEntry entry = new AuditEntry(
            auditId,
            null,
            null,
            null,
            null,
            null,
            null,
            AuditResult.valueOf(result),
            null,
            null,
            null,
            null,
            null,
            Instant.now(),
            maskSensitiveData(details),
            null
        );

        entry = entry.withSignature(signer.sign(entry.toSignableString()));
        auditQueue.offer(entry);
    }

    /**
     * 验证审计记录完整性
     */
    public boolean verifyIntegrity(String auditId) {
        AuditEntry entry = primaryRepository.findById(auditId);
        if (entry == null) return false;

        String expectedSignature = signer.sign(entry.toSignableString());
        return expectedSignature.equals(entry.signature());
    }

    /**
     * 定期归档到冷存储（写入 -> 校验 -> 删除）
     */
    @Scheduled(cron = "0 0 2 * * ?")
    public void archiveToColdStorage() {
        Instant cutoff = Instant.now().minus(30, ChronoUnit.DAYS);
        List<AuditEntry> entries = primaryRepository.findBefore(cutoff);

        String archivePath = "audit/" + LocalDate.now().format(DateTimeFormatter.ISO_DATE) + ".json.gz";
        String checksum = coldStorage.uploadCompressed(archivePath, entries);

        // 验证上传成功后，才删除本地数据
        if (!coldStorage.verifyChecksum(archivePath, checksum)) {
            log.error("Audit archive checksum mismatch: {}", archivePath);
            throw new AuditArchiveException("Archive verification failed");
        }

        primaryRepository.deleteBefore(cutoff);
    }

    private void asyncWrite() {
        while (!Thread.interrupted()) {
            try {
                AuditEntry entry = auditQueue.take();
                persistWithRetry(entry, 3);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
        }
    }

    private void persistWithRetry(AuditEntry entry, int maxRetries) {
        for (int attempt = 1; attempt <= maxRetries; attempt++) {
            try {
                primaryRepository.save(entry);
                return;
            } catch (Exception e) {
                log.error("Failed to write audit entry (attempt {}/{}): {}", attempt, maxRetries, entry.id(), e);
                if (attempt == maxRetries) {
                    writeToLocalWAL(entry);
                } else {
                    try {
                        Thread.sleep(Duration.ofMillis(100L * attempt));
                    } catch (InterruptedException ie) {
                        Thread.currentThread().interrupt();
                        writeToLocalWAL(entry);
                        return;
                    }
                }
            }
        }
    }

    private void writeToLocalWAL(AuditEntry entry) {
        // 写入本地 WAL 文件兜底，服务重启后重放
        log.warn("Writing audit entry to local WAL: {}", entry.id());
        // 实现：按日期分文件追加写入
    }

    private Map<String, Object> maskSensitiveData(Map<String, Object> context) {
        if (context == null) return Map.of();

        Map<String, Object> masked = new HashMap<>();
        for (Map.Entry<String, Object> entry : context.entrySet()) {
            String key = entry.getKey().toLowerCase();
            Object value = entry.getValue();

            if (key.contains("token") || key.contains("password") || key.contains("secret")) {
                masked.put(entry.getKey(), "***MASKED***");
            } else if (key.contains("ip") && value instanceof String ip) {
                masked.put(entry.getKey(), maskIp(ip));
            } else if (key.contains("email") && value instanceof String email) {
                masked.put(entry.getKey(), maskEmail(email));
            } else {
                masked.put(entry.getKey(), value);
            }
        }
        return masked;
    }
}
```

**关键改进**：
- 使用虚拟线程执行器替代手动 Thread，支持优雅关闭。
- 写入失败时重试 3 次，最终写入本地 WAL，避免 `auditQueue.poll()` 取错记录。
- 归档采用“写入 -> 校验 checksum -> 删除本地”三段式，防止数据丢失。
- `AuditEntry` 作为不可变 record，通过 `withSignature` 返回新实例。

## 12. 测试与可验证性

受控工程要求“任何输出可审计、可对比、可复现”。测试是可验证性的核心手段，系统必须满足 **80%+ 测试覆盖率**，并遵循 TDD 工作流。

### 12.1 测试分层策略

| 测试类型 | 范围 | 工具 | 目标覆盖率 |
|----------|------|------|------------|
| **单元测试** | 策略引擎、脱敏工具、输出验证器、领域模型 | JUnit 5 + Mockito | 80%+ |
| **集成测试** | 数据库操作、Qdrant/Neo4j 访问、Temporal Activities、Parse Worker gRPC | Testcontainers + Spring Boot Test | 70%+ |
| **契约测试** | 控制平面与数据平面接口、Parse Worker Protobuf | Pact / Protobuf 验证 | 核心契约 100% |
| **E2E 测试** | 代码推送 → 审批 → 发布 → 诊断完整流程 | Playwright + Testcontainers | 关键路径覆盖 |

### 12.2 TDD 工作流

所有新功能必须遵循 RED -> GREEN -> IMPROVE 循环：

1. 编写失败测试（RED）
2. 实现最小代码使测试通过（GREEN）
3. 重构并保证测试通过（IMPROVE）
4. 运行覆盖率检查，确保 >= 80%

### 12.3 关键测试场景

#### 控制平面
- 策略引擎：默认拒绝、允许条件、审批条件、脱敏规则
- 审计服务：签名验证、归档校验、失败重试与 WAL 兜底
- 工作流：暂停/恢复/审批/拒绝/回滚信号处理

#### 数据平面
- 代码解析：每种 Parse Worker 的 AST 输出符合 CodeElement schema
- 图构建：向量索引与图索引一致性校验
- RAG 检索：并发检索结果合并、脱敏、限流降级
- LLM 调用：熔断、超时、降级、输出验证

### 12.4 测试数据与隔离

- 使用 Testcontainers 启动 PostgreSQL、Qdrant、Neo4j、Temporal。
- 每个测试用例使用独立租户 ID 和仓库名，避免状态污染。
- 敏感数据使用工厂方法生成，绝不使用生产数据。

实际 Compose 文件位于 `infrastructure/docker/docker-compose.yml`，已包含：

data-plane 通过环境变量连接 Parse Worker：

```yaml

  JAVA_PARSER_PORT: 9093
  CSHARP_PARSER_HOST: csharp-parser
  CSHARP_PARSER_PORT: 9094
```

### 13.1.1 部署关键约束

- **本地优先**：所有服务均可通过 Docker Compose 在单台机器启动，无需 K8s 或 Azure。
- **镜像固定**：生产构建使用 Dockerfile 中固定的基础镜像版本（如 `eclipse-temurin:21-jdk-alpine`），避免漂移。
- **配置外部化**：数据库、LLM API Key、Parse Worker 地址均通过环境变量注入，禁止硬编码。
- **数据持久化**：PostgreSQL、Qdrant、Neo4j 使用命名卷，避免容器重启丢失数据。
- **虚拟线程基线**：Spring Boot 启用 `spring.threads.virtual.enabled=true`，并在测试环境检测线程钉住。
